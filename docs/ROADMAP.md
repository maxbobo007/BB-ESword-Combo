# BB ESword 路线图

> 目标：做一个跨平台（手机 + Web）、多设备进度同步的应用，通过"填词"记住西语单词和动词变位。
> 本文由 4 个规划 agent（架构、学习设计、产品策略、风险评审）的结论汇总而成，写于 2026-11-25。

## 1. 现状与差距

| 维度 | 完成度 | 现状 |
|---|---|---|
| 跨平台 | ~15% | RN 0.73 bare 工程。只有 Android 骨架，iOS 只有一个 Podfile，没有 Web。从没在真机上跑过 |
| 进度同步 | 0% | 没有账号和后端。进度是一整块 JSON 存在 AsyncStorage 里，整份覆盖，无法合并 |
| 单词记忆 | ~20% | 填字生成器和字母校验能用。没有间隔重复（SRS），"已学"的意思只是"在通关的关卡里出现过" |
| 动词变位 | 0% | 数据结构、引擎、题型都没有 |
| 内容 | ~3% | 20 个名词。MVP 需要约 700 词、约 90 个动词 |
| 质量工程 | ~10% | 配了 jest/eslint/tsc，但没有测试、没有 CI |

**整体完成度约 10–15%。** 能留下来的主要是填字生成器的放置算法、重音/Ñ 比较函数和对局用的数据类型。

## 2. 关键决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 技术栈 | **迁到 Expo（当前稳定 SDK）+ expo-router + TypeScript**，新建工程后把逻辑搬过去 | 现在只有约 1.5k 行代码，迁移成本最低。一套代码同时出 iOS/Android/Web。EAS 云构建在 Windows 上也能出 iOS 包。可以甩掉 RN 0.73 的升级债 |
| 本地数据 | **expo-sqlite 作为唯一真相源**（Web 端用 wasm）。Zustand 只放界面状态和当前对局状态 | 离线优先是同步的地基 |
| 同步模型 | **复习日志只追加**（UUIDv7 作 id + outbox 上传 + 服务端按 id 幂等）。SRS 状态从日志推导；设置按字段取最后写入 | 合并就是取并集，不会丢数据 |
| 后端 | **Supabase**（Postgres + RLS + Auth）。同步层先抽象成接口 | 关系型数据适合词库和变位表，免费档够用。⚠️ 需要实测你所在网络能否稳定访问（见风险 #3） |
| 登录 | 邮箱验证码 + Sign in with Apple，**不依赖 Google** | 国内网络环境；上架 iOS 的要求 |
| SRS 算法 | **FSRS**（ts-fsrs，MIT） | 比 SM-2 准，天然基于复习日志 |
| 主学习路径 | "今日学习"队列：到期卡 + 新卡，**优先排成填字**，放不进网格的词转成逐个填空"快速补练" | 保留"填词"这个核心，又保证当天到期的内容一个不漏 |

## 3. 学习设计

### 动词变位的填词题型（按引入顺序）
1. **只填词尾**：格子里预填词干 `HABL_`，线索"hablar · yo · 现在时"。A1 入门用。
2. **变位表补全**：6 个人称的表，先给 2–3 格示范。每次学新时态或新的不规则动词时当教学页。
3. **变位填字**：线索"tener · nosotros · 简单过去时"，答案 TUVIMOS，和名词混在同一张网格里。A2 起的复习主力。
4. **句子填空**："Ayer yo ___ (comer) paella." → COMÍ。不告诉用哪个时态，训练按时间词判断。中文动词没有时态，这是中国学习者的弱项。

**时态顺序**：
- A1：规则动词现在时 → ser/estar/tener/ir/hacer → 词干变化（e→ie、o→ue、e→i）→ ir a + 原形
- A2：现在完成时 → 简单过去时 → 过去未完成时 → 自反动词
- B1 及以后：将来时、条件式、命令式、虚拟式

vosotros 做成开关：选"西班牙"时打开，选"拉美"时关闭。

### 记忆机制
- **卡片粒度**：词汇一词一卡（中文 → 西语）。变位按"动词 × 时态"一卡，但每个人称的错误都记日志，答错的人称下次优先出。
- **评分映射**：

  | 作答情况 | FSRS 评分 |
  |---|---|
  | 一次答对、没用提示 | Good |
  | 错 1 次、用了字母提示、或只漏了重音 | Hard |
  | 揭示答案或错 2 次以上 | Again |

- **"已掌握"的定义**：FSRS 稳定度 ≥ 21 天。首页只显示"已掌握 N 个"。

### 重音策略（修正 PR #2 的临时做法）
PR #2 让输入 E 就能匹配 É，只是为了先能通关。但变位里重音能区分意思（hablo 是"我说"，habló 是"他说过"），所以要改成：
- 元音长按弹出 á é í ó ú ü，实体键盘可以直接输入。
- 漏了重音时格子标黄、显示"缺少重音"，评分记 Hard，不判全错。
- 设置里加"严格重音"开关。

### 计分与提示
- 去掉时间扣分。主目标是"今日复习完成"，经验值和正确率是次要信息。
- 提示分级：首字母 → 随机给一个字母 → 听发音（expo-speech 调系统 TTS）→ 揭示整词。每一级都会影响评分。

## 4. MVP 范围

**要做**：
- iOS/Android/Web 三端
- 离线可用
- FSRS
- 填字 + 快速补练 + 变位四种题型
- 约 700 个 A1–A2 词
- 约 90 个动词（含 25 个高频不规则动词），覆盖现在时、简单过去时、现在完成时
- 系统 TTS
- 账号与同步
- 删除账号、隐私政策

**不做或推迟**：
- 社交 / 排行榜 / 好友对战（**砍掉**）
- 自定义词库
- 录音资源
- B2 以上内容
- 虚拟式 / 复合时态（完成时除外）
- 付费
- 成就系统（`Leaderboard` / `Achievement` 类型先冻结）

## 5. 里程碑（按 solo 开发者 + AI 助手、每周 10–15 小时估算）

| 阶段 | 目标 | 交付物 | 验收标准 | 工作量 |
|---|---|---|---|---|
| **M0 底座** | 三端跑通 | Expo 新工程；迁入生成器和字母比较函数；生成器加相邻格/首尾格检查、可传随机种子、放置失败可感知；Jest 单测；GitHub Actions（tsc + lint + jest） | 三端都能玩完一局；生成器属性测试 1000 组：不出伪单词、不悄悄丢词；CI 绿 | 1–1.5 周 |
| **M1 单词 SRS** | 每天能用的单词闭环 | SQLite schema；内容管线（CSV/JSON → 内容包，带 `content_version`）；ts-fsrs；复习日志；"今日学习"首页、复盘页、快速补练；新重音输入；约 300 词 | 自己连续用 7 天；重启后进度不丢；SRS 有单测 | 2–3 周 |
| **M2 动词变位** | 第二条学习线 | 变位规则引擎（规则词尾 + 词干变化 + 拼写变化 + 不规则覆盖表），输出静态 JSON；四种题型；50 个动词 × 3 个时态；内容扩到约 700 词 | 和独立来源全量比对 100% 一致；变位卡进入同一个 SRS 队列 | 2–3 周 |
| **M3 同步** | 多设备一致 | Supabase Auth + RLS；outbox 上传；按 `server_seq` 增量拉取；启动、回到前台、做完一局时同步 | 手机做 20 题，Web 刷新后一致；断网做题、联网后自动补传；冲突测试清单全部通过 | 1.5–2 周 |
| **M4 打磨与内测** | 能给别人用 | 新手引导、统计页、深色模式、Sentry、隐私政策、删除账号、数据导出；约 90 个动词 | 3–5 位朋友内测 2 周，没有阻断级 bug | 2–3 周 |

**合计约 10–12 周。** Web 版在 M3 后就可以部署（Cloudflare Pages / Vercel）。

Google Play 新个人开发者账号要先完成封闭测试（约 12 名测试者、14 天），要提前安排。App Store 最后上：先用 TestFlight 内测，自己连续用 30 天以上再考虑公开上架。

## 6. 风险与对策（按可能性 × 影响排序）

1. **生成器扛不住变位词**：长词、共享字母少、带重音。对策：补相邻格检查、回溯或多次重试取最优、放置率低于阈值就换词重生成、放不下的词转去快速补练、加属性测试。
2. **变位或中文释义出错**：教错会毁掉信誉。对策：变位用引擎生成，再和独立来源全量比对。释义走"LLM 起草 → 人工审 → 抽查"，每条带 `reviewed` 标记；App 内加"报错"按钮。
3. **国内网络访问后端不稳**：Firebase 和 Google 登录基本不可用；Supabase 托管版也要实测。对策：同步层抽象成接口，离线优先；不行就换 Supabase 自部署或国内云。
4. **同步丢数据**：对策：复习日志只追加，存储带 `schemaVersion` 和迁移逻辑。
5. **数据授权**：商业词书不能用；Wiktionary 是 CC BY-SA，有传染性；有些变位数据库是非商业许可。对策：频率表只用来排序，释义自编；在 `data/LICENSES` 里逐条记录来源。⚠️ 各项许可证上线前要自己再核实一遍。
6. **商店审核**：有账号就必须能在 App 内删除账号、提供隐私政策、做 Sign in with Apple；国内安卓市场还要软著。对策：这些和账号功能在同一个版本上线。
7. **范围膨胀**：对策：严格按 MVP 清单做，新想法统一记进 backlog。
